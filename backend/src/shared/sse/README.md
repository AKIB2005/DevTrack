# Replay stream v2 writer

`SSE_V2_WRITER_ENABLED=true` enables the experimental v2 writer; it is disabled by default. Do not enable it during a rolling deployment with legacy writers. Drain or fence every legacy writer before enabling v2, and fence v2 writers before rolling back. The existing frontend prototype is not generation-aware and must not be used as a strict v2 sequence gate.

Each v2 stream entry stores `protocolVersion`, `generation` and `sequence`. A single-key Redis script reads the tail and appends the next sequence in the same generation. An empty stream or legacy tail starts a fresh UUID generation. The script refreshes the stream's 300-second TTL; trimming retains the newest entry and therefore its generation and sequence. Redis stream IDs remain the replay cursors. Legacy entries retain their existing format.

Stream expiration, data loss, manual deletion, and an intervening legacy write can start a new generation. A generation is not proof that all events were delivered. Redis failures, delayed publication after append, mixed writers, and retention loss still require separate recovery handling.

Clients opting in with `replayProtocol=2` request verified replay independently of the writer flag. The server atomically checks that the opaque cursor still names a retained entry and reads at most 101 later entries. If the cursor is invalid or absent, the replay exceeds 100 entries, or replay fails, the server sends an ID-less named SSE event `sse_recovery_required` with JSON `{ "protocolVersion": 2, "reason": "invalid_cursor" | "cursor_unavailable" | "replay_limit_exceeded" | "replay_failed", "replayComplete": false }`. This is not a successful recovery or a replacement for lost events. The client must reconcile application state and expose failure when it cannot do so; a runtime-state snapshot alone cannot reconstruct every SSE event type. An absent cursor does not distinguish trimming, expiry, deletion, recreation, or a foreign cursor. A retained cursor also cannot prove completeness if entries were deleted after it, the stream was recreated with a reused ID, or events were never appended. Mixed writers still require fencing. An empty verified suffix means only that no later entries were present at the atomic read; it is not proof of historical completeness.

All serving instances must support `replayProtocol=2` before clients rely on verified replay; older instances ignore the parameter and provide legacy replay. Writer-flag consistency and fencing remain necessary during rollout and rollback, independently of this replay opt-in.
